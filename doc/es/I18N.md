# I18N.md — Arquitectura multiidioma de Okeymoney

> 🌐 **Otros idiomas:** [English](../en/I18N.md)

Referencia técnica del sistema de internacionalización (`App.i18n`) y receta
paso a paso para añadir un idioma nuevo. Leer junto a [`tecnico.md`](tecnico.md)
§5 (integración técnica) y [`SPEC.md`](SPEC.md) §3–§4 (reglas de producto y
accesibilidad, que aplican **en todos los idiomas**).

**Estado actual**: español (`es`, por defecto) e inglés (`en`). El sistema
está diseñado para más de dos idiomas, pero hoy tiene varios puntos con
lógica binaria `es`/`en` que se han ido generalizando para soportar un
tercer idioma sin tocar el código de UI — ver §4. Lo único que aún depende
del inglés es la `meta` de la aplicación (p. ej. el símbolo del euro `€` en
los precios), porque Okeymoney es una app de dinero en euros y no se ha
previsto cambiar de moneda junto con el idioma.

**Política de idioma**:

- **Interfaz de usuario (UI)**: multiidioma — todos los textos visibles para
  el usuario final existen en cada idioma soportado (`es`, `en`…).
- **Código técnico**: **siempre en inglés** — nombres de variables,
  funciones, objetos JavaScript y, **crucialmente, las claves de
  `strings.<locale>.js`** deben estar en inglés. Los valores de las claves
  son el texto traducible (UI), pero la clave misma es código técnico y por
  tanto va en inglés.

  ```js
  // ✅ Correcto — clave en inglés, valores en el idioma del archivo
  // strings.es.js
  App.i18n.register({
    balanceLabel: 'Tienes',
    editHint: 'Toca el número para cambiarlo'
  }, 'es');
  // strings.en.js
  App.i18n.register({
    balanceLabel: 'You have',
    editHint: 'Tap the number to change it'
  }, 'en');
  ```

  Esta distinción permite que `App.i18n.t('balanceLabel')` sea legible en el
  código fuente, independientemente del idioma activo.

## 0. Sistema multi-archivo

Okeymoney usa el patrón multi-archivo del que Apptonomia hizo el cambio en
v4: cada idioma tiene **un archivo separado** y solo el del locale activo
se envía realmente al navegador (los otros también se cargan hoy, pero
`register` solo rellena el slot del locale en cuestión).

### Estructura

```
strings.es.js          ← textos ES de la app (registra en locale 'es')
strings.en.js          ← textos EN de la app (registra en locale 'en')

legal/strings.es.js    ← textos ES de la página legal
legal/strings.en.js    ← textos EN de la página legal
```

### Ventajas sobre el monolítico

- **Mantenimiento independiente**: un traductor solo edita el archivo del
  idioma que conoce — no ve el otro idioma mezclado.
- **Diffs limpios**: un cambio en la traducción inglesa muestra solo los
  textos cambiados en inglés, no todo el archivo.
- **Escalabilidad**: añadir un idioma es crear `strings.<locale>.js` por
  cada "scope" (raíz y `legal/`), sin tocar los otros idiomas.

### Patrón de `strings.<locale>.js`

```js
/* ============================================================
   Okeymoney — Textos (ES)
   Archivo específico del idioma. Se carga de forma síncrona
   desde index.html (sin document.write) antes de data.js y
   app.js para que App.i18n.register haya poblado el
   diccionario cuando cualquier código de UI llame a
   App.i18n.t().
   ============================================================ */
(function () {
  'use strict';
  App.i18n.register({
    title: 'Okeymoney',
    tabs: { home: 'Mi dinero', goals: 'Mis metas', /* ... */ },
    // ... resto de claves ES
  }, 'es');
})();
```

El segundo argumento de `register(dict, locale)` indica **a qué idioma** se
registra. `App.i18n.js` se encarga de almacenarlo en `DICT[locale]` y
mantener el fallback a español cuando una clave falta.

## 1. Piezas del sistema

```
assets/js/i18n.js            # Núcleo: App.i18n (detección, persistencia, t/pick/apply)
assets/js/money.js           # Registra también sus textos por idioma (money.*)
strings.es.js                # Textos ES de la app
strings.en.js                # Textos EN de la app
index.html                   # Selector de idioma (N botones generados) + carga de scripts
legal/index.html             # Mismo patrón, cargado con legal/strings.<locale>.js
data.js                      # Datos "neutros" (ids, emojis) — el texto va en strings
app.js                       # Usa App.i18n.t()/.pick()/.locale() para leer/generar texto
```

### 1.1 `assets/js/i18n.js` — núcleo

```js
var SUPPORTED = ['es', 'en'];          // idiomas activables
var DEFAULT_LOCALE = 'es';             // fallback si falta una clave o el idioma detectado no está soportado
var BCP47 = { es: 'es-ES', en: 'en-US' }; // mapeo a códigos BCP47 para speechSynthesis
var LABEL = { es: 'Español', en: 'English' }; // texto del botón de idioma
var FLAG = { es: '🇪🇸', en: '🇬🇧' };   // emoji del botón de idioma
```

- **Detección** (`detect()`): recorre `navigator.languages`, se queda con
  el prefijo de 2 letras del primero que esté en `SUPPORTED`. Si ninguno
  coincide, usa `DEFAULT_LOCALE`.
- **Persistencia** (`locale()` / `setLocale()`): `localStorage['okeymoney:locale']`.
  Si hay un valor guardado y soportado, gana sobre la detección.
  `setLocale()` guarda y **recarga la página** (no hay re-render en caliente).
- **`register(dict, locale)`**: registra el diccionario en el locale
  indicado. El núcleo de Okeymoney (`assets/js/i18n.js`) ya viene con
  `core.*` y `feedback.*` pre-registrados en `es` y `en`. Cada
  `strings.<locale>.js` extiende el diccionario con sus propias claves.
- **`t(key)`**: busca `key` (con puntos, p. ej. `'categories.food'` o
  `'core.back'`) en el idioma activo. Si no está, cae a `DEFAULT_LOCALE`
  (español). Si tampoco está, devuelve la propia `key` (para que las
  claves rotas se vean a simple vista en pantalla). Si el valor es un
  array, lo une con `', '` (pensado para depurar, no para UI).
- **`pick(key)`**: como `t`, pero para claves que son un **array** de
  variantes (p. ej. `feedback.success`) — devuelve una al azar. Lo usa
  `feedback.js` para los mensajes de ánimo/acierto.
- **`apply(root)`**: aplica `data-i18n` (→ `textContent`) y
  `data-i18n-aria` (→ `aria-label`) a todo el DOM bajo `root` (por defecto
  `document`). Se ejecuta sola en `DOMContentLoaded`. También pone
  `document.documentElement.lang` y, si `<html>` tiene
  `data-i18n-title="clave"`, fija `document.title = t(clave) + ' | Okeymoney'`.
- **`lang()`**: devuelve el código BCP47 del locale activo (usado por
  `App.tts.speak()` para elegir la voz de `speechSynthesis`). Se basa en
  el mapa `BCP47` con fallback a `DEFAULT_LOCALE`.

### 1.2 Claves comunes (`core.*`, `feedback.*`)

Definidas una vez en `i18n.js`; **no redefinir** en `strings.<locale>.js`.
Todas las subclaves van en inglés (código técnico):

| Clave | ES | EN |
|---|---|---|
| `core.back` | ← Volver | ← Back |
| `core.close` | Cerrar | Close |
| `core.next` | Siguiente → | Next → |
| `core.save` | Guardar | Save |
| `core.cancel` | Cancelar | Cancel |
| `core.understood` | Entendido | Got it |
| `core.listen` | 🔊 Escuchar | 🔊 Listen |
| `core.listenInstructions` | Escuchar las instrucciones | Listen to the instructions |
| `core.loading` | Cargando… | Loading… |
| `core.dataProtection` | Protección de datos | Data protection |
| `feedback.success` (array) | ¡Muy bien! / ¡Genial! / … | Well done! / Great! / … |
| `feedback.encourage` (array) | Casi. ¡Inténtalo otra vez! / … | Almost. Try again! / … |

### 1.3 `strings.<locale>.js` (raíz y `legal/`)

Okeymoney tiene **dos scopes** de textos:

- `strings.<locale>.js` en la raíz: la app (tres pestañas + asistente).
- `legal/strings.<locale>.js`: la página "Protección de datos" (un único
  archivo HTML en `legal/index.html`).

Ambos siguen el mismo patrón. El gold reference es `strings.es.js`.

```js
/* strings.es.js */
(function () {
  'use strict';
  App.i18n.register({
    title: 'Okeymoney',
    tabs: { home: 'Mi dinero', goals: 'Mis metas', /* ... */ },
    home: { balanceLabel: 'Tienes', /* ... */ },
    categories: { food: 'Comida', /* ... */ },
    // ... resto de claves
  }, 'es');
})();
```

**Importante**: las claves (`tabs.home`, `home.balanceLabel`,
`categories.food`…) son código técnico y van siempre en inglés,
independientemente del idioma de la UI. Los valores son el texto
traducible para el usuario.

- Debe existir siempre la clave `title` (la usa `data-i18n-title` para el
  `<title>`).
- Las **claves deben coincidir exactamente** entre todos los
  `strings.<locale>.js` del mismo scope (verificado por `scripts/check.js`
  §2).
- Objetos anidados funcionan como namespaces: `tabs: { home: '…' }` se lee
  con `t('tabs.home')`.
- **Nunca** un array cuando se necesita indexar por posición (`t()` uniría
  el array con comas). Para tablas indexadas por número usar un objeto con
  claves de texto: `{ 0: '', 1: 'miles', 2: 'millones' }` y leer con
  `t('grupoEtq.' + i)`.
- El inventario de claves visibles en la app viene dado por el HTML
  (`data-i18n`/`data-i18n-aria`) **y** por las llamadas a `App.i18n.t(...)`
  en `app.js`. Si añades un texto nuevo, añade la clave en ambos
  `strings.<locale>.js` antes de mergear.

### 1.4 Dónde vive el texto: `data.js` vs `strings.<locale>.js`

Okeymoney separa "lo que cambia por idioma" (texto visible) de "lo que no
cambia" (ids, emojis, importes en céntimos). `data.js` solo contiene
**datos neutros**:

- `DATA.categories`: `[{ id: 'food', icon: '🍎' }, …]`. El nombre visible
  sale de `App.i18n.t('categories.' + c.id)`.
- `DATA.goalIcons`: emojis de las metas (`['🎮', '⚽', …]`).
- `DATA.learnTeaser`: ids de las tarjetas de "Aprender" (`['change',
  'budget', 'needsWants']`). El texto visible sale de
  `App.i18n.t('learn.teaser.' + id)`.

Por convención, **el texto siempre va en `strings.<locale>.js`**, no en
`data.js`. Esto mantiene `data.js` realmente "locale-neutral" — añadir un
idioma no requiere tocarlo.

### 1.5 HTML: atributos `data-i18n*`

```html
<html lang="es" data-i18n-title="title">
...
<h1 data-i18n="title">Okeymoney</h1>
<button data-i18n-aria="home.editBalanceAria" aria-label="Cambiar cuánto dinero tienes">…</button>
```

El texto/`aria-label` por defecto en el HTML es en español (idioma por
defecto). `apply()` lo sobrescribe al arrancar. Atributos que `apply()`
**no** cubre (hay que fijarlos a mano en `app.js`): `placeholder` de
`<input>` (las metas lo usan) y los textos generados dinámicamente en cada
re-render.

### 1.6 Orden de carga de scripts (obligatorio)

```html
<script src="assets/js/utils.js"></script>
<script src="assets/js/i18n.js"></script>
<script src="assets/js/tts.js"></script>
<script src="assets/js/storage.js"></script>
<script src="assets/js/feedback.js"></script>
<script src="assets/js/money.js"></script>
<script src="strings.es.js"></script>
<script src="strings.en.js"></script>
<script src="data.js"></script>
<script src="app.js"></script>
```

`i18n.js` carga antes que `tts.js`/`feedback.js`/`money.js` (leen el
idioma activo). Los dos archivos `strings.<locale>.js` cargan de forma
síncrona **antes** de `data.js` y `app.js`, así que `App.i18n.register` ya
rellenó el diccionario cuando cualquier código de UI llama a
`App.i18n.t()`. `document.write` se evita a propósito: Chrome y Firefox
procesan los `<script>` inyectados por `document.write` de forma asíncrona,
lo que haría que `t()` devolviera la clave literal durante el primer
render.

### 1.7 Selector de idioma (en `index.html`)

`app.js` genera los botones del selector **dinámicamente** desde
`App.i18n.SUPPORTED`, leyendo `App.i18n.LABEL` y `App.i18n.FLAG` para la
etiqueta y la bandera. Añadir un idioma no implica editar el HTML — solo
extender `SUPPORTED`/`LABEL`/`FLAG` en `i18n.js` (ver §5).

```js
// app.js (resumen)
SupportSelector
function renderLanguageSelector() {
  var active = App.i18n.locale();
  $('#langRow').innerHTML = '';
  App.i18n.SUPPORTED.forEach(function (loc) {
    var btn = document.createElement('button');
    btn.setAttribute('aria-pressed', String(active === loc));
    btn.textContent = (App.i18n.FLAG[loc] || '') + ' ' + (App.i18n.LABEL[loc] || loc);
    btn.addEventListener('click', function () { App.i18n.setLocale(loc); });
    $('#langRow').appendChild(btn);
  });
}
```

`legal/index.html` no tiene selector de idioma: por su propia naturaleza
(página informativa legal) se muestra en el idioma del navegador y, si
fuera necesario traducirla, seguiría el mismo patrón de archivos
multi-idioma.

## 2. Formato de números y dinero: NO es solo traducción

Okeymoney trabaja **siempre con importes en céntimos enteros** (nunca con
decimales en coma flotante) y formatea la salida según el locale. La regla
clave:

- **Separador decimal**: español usa `,` (`1,50 €`), inglés usa `.`
  (`1.50 €`). El mapeo `DECIMAL_SEP` vive en `assets/js/money.js` y debe
  extenderse cuando se añade un idioma (Paso 4 de §5).
- **Sin escala numérica**: las cantidades que maneja Okeymoney en v1 son
  pequeñas (`MAX_CENTS = 9999999` → 99 999,99 €), por lo que no entran en
  juego los problemas de "escala larga" vs "escala corta" que tiene
  Apptonomia al leer números grandes en voz alta. Si en el futuro se
  añaden cuantías mayores o se introduce TTS, **es** un punto a
  reintroducir aquí.
- **Moneda**: Okeymoney es una app de euros (`€`). Cambiar de moneda
  junto con el idioma no está previsto en v1 — si alguna vez se hace, se
  modela como un par `(locale, currency)` en un mapa aparte, no como
  consecuencia del idioma.

**Regla general**: antes de mostrar un número o un importe en un idioma
nuevo, comprobar cómo lo escribiría de verdad un hablante nativo: separar
miles y decimales como toca.

---

## 3. Contenido cultural: NO traducir literalmente

Okeymoney tiene poco contenido "cultural" en v1 (las categorías y los
emojis son los mismos en todos los idiomas). Sin embargo, las **categorías
de gasto** y los **nombres de las metas** son elecciones del usuario y no
del traductor, así que la regla de Apptonomia sigue aplicando en spirit:

- **Nunca** traducir literalmente un texto que dependa de un juego de
  palabras, una rima o una referencia cultural — escribir un contenido
  genuino del idioma destino con la misma intención pedagógica.
- **Sí** traducir directamente palabra por palabra lo que es vocabulario
  llano (los nombres de "Comida", "Ocio", "Transporte", etc.).

## 4. Puntos con lógica binaria `es`/`en` (estado de la generalización)

Esta es la lista de sitios que todavía bifurcan por idioma. La expansión
a un tercer idioma **no** los toca desde la app — pero hay que añadir
una entrada en cada mapa para el nuevo locale.

| Archivo:línea | Qué hace | Qué hay que añadir cuando entre un 3er idioma |
|---|---|---|
| `assets/js/i18n.js` `SUPPORTED` | `['es', 'en']` | Añadir el código: `['es', 'en', 'fr']` |
| `assets/js/i18n.js` `BCP47` | `{ es: 'es-ES', en: 'en-US' }` | Añadir `'fr': 'fr-FR'` |
| `assets/js/i18n.js` `LABEL` | `{ es: 'Español', en: 'English' }` | Añadir `'fr': 'Français'` |
| `assets/js/i18n.js` `FLAG` | `{ es: '🇪🇸', en: '🇬🇧' }` | Añadir `'fr': '🇫🇷'` |
| `assets/js/i18n.js` `core`/`feedback` | bloques `es` y `en` | Añadir un bloque `fr` con las mismas claves |
| `assets/js/money.js` `DECIMAL_SEP` | `{ es: ',', en: '.' }` | Mapa por idioma (p. ej. `fr: ','` o `fr: ' '`) |
| `assets/js/i18n.js` `DEFAULT_LOCALE` | `'es'` | No se toca — siempre español, como fallback seguro |

`app.js` y `index.html` se han reescrito para generar el selector y leer
el locale desde `App.i18n.SUPPORTED`, así que no quedan puntos binarios
ahí.

## 5. Receta: añadir un idioma nuevo (ejemplo: francés, `fr`)

Cada paso es mecánico salvo el 4 (contenido) y el 5 (separador decimal).

### Paso 1 — Registrar el idioma en el núcleo

En `assets/js/i18n.js`:

```js
var SUPPORTED = ['es', 'en', 'fr'];
var BCP47 = { es: 'es-ES', en: 'en-US', fr: 'fr-FR' };
var LABEL = { es: 'Español', en: 'English', fr: 'Français' };
var FLAG = { es: '🇪🇸', en: '🇬🇧', fr: '🇫🇷' };
```

Añadir un bloque `fr` al diccionario `core` / `feedback` (mismas claves que
`es` y `en`):

```js
fr: {
  core: {
    back: '← Retour', close: 'Fermer', next: 'Suivant →',
    save: 'Enregistrer', cancel: 'Annuler', understood: 'Compris',
    listen: '🔊 Écouter', listenInstructions: 'Écouter les instructions',
    loading: 'Chargement…', dataProtection: 'Protection des données'
  },
  feedback: {
    success: ['Bravo !', 'Génial !', "Tu l'as fait !", 'Super !'],
    encourage: ['Presque. Essaie encore !', "Pas grave. Encore une fois !"]
  }
}
```

### Paso 2 — Selector de idioma

No requiere cambio: `app.js` ya genera los botones desde `SUPPORTED`. Si
el idioma se añade en `LABEL` y `FLAG`, aparece automáticamente al recargar.

### Paso 3 — `strings.fr.js` raíz

Crear `strings.fr.js` en la raíz con las **mismas claves** que
`strings.es.js` / `strings.en.js` (mismos nombres, misma estructura
anidada). Usar `strings.es.js` como gold reference para la forma.

### Paso 4 — `legal/strings.fr.js`

Crear `legal/strings.fr.js` con las mismas claves que
`legal/strings.es.js` / `legal/strings.en.js`.

### Paso 5 — Separador decimal

En `assets/js/money.js`:

```js
var DECIMAL_SEP = { es: ',', en: '.', fr: ',' };  // o ' ' según convenga
```

Si el idioma usa un separador de miles (espacio fino, etc.), generalizar
también `format()` para usarlo — hoy Okeymoney muestra importes pequeños
y no necesita separador de miles.

### Paso 6 — Actualizar `sw.js`

Subir `VERSION` (`'okeymoney-v1'` → `'okeymoney-v2'`, por ejemplo) y
añadir los nuevos `strings.fr.js` al array `FILES`:

```js
var VERSION = 'okeymoney-v2';

var FILES = [
  // … existente …
  './strings.fr.js',
  './legal/strings.fr.js',
  // … resto …
];
```

### Paso 7 — Añadir el `<script>` en `index.html` y `legal/index.html`

Cada archivo `strings.<locale>.js` se carga de forma síncrona **antes** de
`data.js` y `app.js` (sin `document.write`). Añadir la línea en el mismo
orden que `es` y `en`:

```html
<!-- index.html -->
<script src="strings.es.js"></script>
<script src="strings.en.js"></script>
<script src="strings.fr.js"></script>
<script src="data.js"></script>
<script src="app.js"></script>
```

```html
<!-- legal/index.html -->
<script src="strings.es.js"></script>
<script src="strings.en.js"></script>
<script src="strings.fr.js"></script>
```

### Paso 8 — Verificar paridad de claves

`scripts/check.js` (§2) valida que **todos** los `strings.<locale>.js` del
mismo scope (raíz y `legal/`) tengan exactamente las mismas claves. Al
añadir `fr`, el check pasa a comparar 3 archivos sin tocar nada del
script.

```bash
node scripts/check.js
```

Si alguna clave falta en `fr`, `check.js` lo listará con detalle ("only in
strings.es.js: …", "only in strings.fr.js: …").

### Paso 9 — Verificación funcional

- Selector de idioma: el tercer botón aparece en `index.html` y persiste
  la elección en `localStorage['okeymoney:locale']`.
- Recargar con `fr` activo: la UI se muestra en francés, no queda ni una
  clave en español a la vista.
- Wizard de "Registrar un gasto": los importes se formatean con el
  separador decimal correcto.
- Modo offline (PWA instalada): los nuevos `strings.fr.js` están en el
  `FILES` del service worker y funcionan sin red.

## 6. Qué NO hacer

- No dar por buena una traducción automática de números, importes o
  plantillas con placeholders sin comprobar la convención real del
  idioma (§2).
- No dejar una clave sin su equivalente en **todos** los idiomas
  soportados — el fallback a español oculta el hueco en vez de fallar
  de forma visible, y el `check.js` lo cazará en CI.
- No usar arrays en `strings.<locale>.js` para datos indexados por
  posición/número (`t()` los aplana con `join(', ')`); usar un objeto con
  claves de texto (`{0:'', 1:'...'}`).
- No añadir un idioma nuevo sin extender primero `SUPPORTED`, `BCP47`,
  `LABEL`, `FLAG` en `i18n.js` y `DECIMAL_SEP` en `money.js` (§4): si no,
  el idioma nuevo heredará en silencio el comportamiento del idioma por
  defecto.
- No traducir literalmente categorías o nombres de metas que dependan de
  un juego de palabras o una referencia cultural — escribir contenido
  propio del idioma destino con la misma intención pedagógica.
- No añadir un `<script>` para un `strings.<locale>.js` después de
  `data.js` o `app.js`: `App.i18n.t()` devolvería la clave literal
  durante el primer render.
- No olvidar subir `VERSION` en `sw.js` y añadir el archivo a `FILES`
  al crear un `strings.<locale>.js` nuevo: los PWAs instalados con la
  versión vieja no lo descargarían hasta vaciar la caché.
